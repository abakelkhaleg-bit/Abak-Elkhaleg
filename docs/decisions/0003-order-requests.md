# ADR 0003 — حفظ طلب أولي (OrderRequest) عند فتح واتساب

- **الحالة:** معتمد من المالك (2026-10-15)
- **السياق:**
  - الطلب يتم عبر واتساب دون دفع إلكتروني، والطلب الأصلي ترك حفظ الطلب الأولي اختياريًا.
  - المالك اختار الحفظ.
- **القرار:**
  - عند ضغط العميل «اطلب عبر واتساب» ينشئ الخادم `OrderRequest`:
    - رقم مرجعي `AK-…`.
    - snapshot للبنود بأسعار القاعدة.
    - الإجمالي محسوب على الخادم.
    - بيانات العميل.
    - الحالة `opened_in_whatsapp`.
  - الرقم المرجعي يظهر داخل رسالة واتساب، فيستطيع الأدمن مطابقة الرسالة بالطلب.
  - **لا يُخصم المخزون** عند الإنشاء.
  - الأدمن يغيّر الحالة يدويًا:
    - «تأكيد» يخصم المخزون ذريًا داخل معاملة، مع حركة `sale`، ومحمي من التكرار.
    - «إلغاء» يعيد المخزون إن كان الطلب مؤكدًا، مع حركة `order_cancel_restore`.
  - الطلبات المفتوحة الأقدم من 7 أيام تُعرض «منتهية». الحالة محسوبة وليست مخزنة، ويبقى التأكيد ممكنًا.
- **الغرض:** ربط رسائل واتساب بطلبات موثقة، وخصم المخزون فقط عند البيع الفعلي، وإظهار عدد الطلبات المؤكدة بصدق.
- **ما لا نفعله:**
  - لا نقول للعميل إن الطلب أُرسل أو تأكد.
  - لا نعرض «مبيعات» إلا للطلبات المؤكدة يدويًا.
  - لا تقارير مالية في الإصدار الأول.
- **العواقب:**
  - تخزين بيانات شخصية، فتلزم حماية الإدارة، وحذف PII، وسياسة احتفاظ (SECURITY §10).
  - إضافة rate limit لإنشاء الطلبات لمنع السبام.
  - صفحة «الطلبات» تُضاف للوحة الإدارة في المرحلة 6.

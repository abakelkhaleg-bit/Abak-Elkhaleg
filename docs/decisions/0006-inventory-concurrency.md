# ADR 0006 — المخزون: تحديثات ذرية شرطية ومعاملات

- **الحالة:** مقترح (يُعتمد مع الخطة)
- **السياق:** يجب منع:
  - الكميات السالبة.
  - البيع فوق المتاح.
  - تكرار الخصم.
  - حالات السباق.
  
  ويجب أن يُكتب تحديث المخزون وسجل الحركة والتنبيه معًا أو لا يُكتب شيء.
- **القرار:**
  - كل تغيير للمخزون يمر عبر `inventory.service` فقط.
  - التحديث بفلتر شرطي يتضمن `stockQuantity: {$gte: -delta}`، مع `$inc` و`arrayFilters`، فيصبح الفحص والتعديل عملية ذرية واحدة.
  - التحديث والحركة والتنبيه والحقول المحسوبة كلها داخل `session.withTransaction()`.
  - **يُشترط replica set:** Atlas افتراضيًا، أو `--replSet` محليًا، أو `MongoMemoryReplSet` في الاختبارات. فحص عند بدء التشغيل.
  - تأكيد الطلب idempotent بانتقال حالة شرطي، مع فهرس فريد على `{orderId, variantId, movementType}`.
  - التنبيهات بلا تكرار بفهرس فريد جزئي (`resolvedAt: null`)، مع دورة فتح وإغلاق موثقة في DATABASE §3.5.
- **العواقب:**
  - لا يعمل التطبيق بكامل وظائفه على MongoDB مستقلة، وهذا موثق في DEPLOYMENT.
  - اختبار تزامن S8 إلزامي.

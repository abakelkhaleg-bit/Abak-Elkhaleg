# الاختبارات — متجر «عطور عبق الخليج»

## 1. الأدوات
| النوع | الأداة | البيئة |
|---|---|---|
| Unit | Vitest | Node، بدون قاعدة بيانات |
| Integration | Vitest + `mongodb-memory-server` (`MongoMemoryReplSet`، عقدة واحدة) | قاعدة حقيقية في الذاكرة تدعم المعاملات، وCloudinary مُحاكى |
| E2E | Playwright (Chromium؛ وWebKit للموبايل في المرحلة 8) | `next build && next start` على قاعدة اختبار مُعبأة بالـseed، وCloudinary مُحاكى عبر متغير بيئة يوجه الخدمة إلى محاكٍ محلي |
| Accessibility | `@axe-core/playwright` | داخل E2E |
| Lint / Types | ESLint، `tsc --noEmit` | |

**لماذا Vitest وليس Jest:** إعداده أبسط مع TypeScript وESM، وأسرع، ومتوافق مع Next. تُختبر Server Components بالـE2E، أما الخدمات فتُختبر مباشرة.

## 2. الأوامر (تُعرّف في `package.json` في المرحلة 1)
```
npm run lint
npm run typecheck
npm run test              # unit + integration
npm run test:unit
npm run test:integration
npm run test:e2e          # يبني ويشغل التطبيق ثم Playwright
npm run build
```

## 3. القواعد
- لا `test.skip`، ولا `.only`، ولا تعطيل اختبار كحل. ESLint يمنع `.only`.
- كل خطأ يُكتشف يُضاف له اختبار انحدار (regression) قبل إصلاحه.
- لا تُعلن نتيجة اختبار إلا بعد تشغيله فعليًا ونسخ ملخص مخرجاته في تقرير المرحلة وفي PROGRESS.
- الاختبارات لا تعتمد على Cloudinary أو MongoDB حقيقيين أو على الإنترنت.
- كل ملف integration يبدأ بقاعدة نظيفة: `beforeEach` يحذف كل المجموعات، ثم `syncIndexes`.

### 4.8 أدوات مساعدة (Unit)
- تطبيع العربية:
  - «إِطْلَالَة» تصبح «اطلاله».
  - «عـــود» تصبح «عود».
  - «مسكى» و«مسكي» متطابقتان.
- تحويل slug.
- تنسيق المال `ar-EG`.
- تحويل الهاتف المصري إلى E.164.
- حساب نسبة الخصم.
